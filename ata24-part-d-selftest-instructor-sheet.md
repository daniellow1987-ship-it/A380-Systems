## Feedback on the master prompt (ambiguities / friction met while executing it)

1. **The delivery format collides with the self-test order.** Phase 5 says "Self-test checklist must all pass before you output Part C", but the checklist can only be executed on the finished file, and Part D (the log) comes after Part C. In a single chat reply there is no way to run a browser; in this rig I could. The prompt should say either "tick what you verified by reasoning" or explicitly allow a tool-run phase between C and D.
2. **Two note sets with conflicting terminology.** The input gives L1 (BCRU 1/2/ESS + TR 2) and L2 (TR 1/2/ESS, "three identical TRs") without saying which name to use in the UI. I chose L1 names (input block said primary) and aliased L2 in the glossary. The prompt's Phase 0 should include a rule: "when two note sets disagree, name the primary, show both, never merge silently". Same for battery voltage (28 VDC in L1 vs 24 V nominal in L2) and STAT INV target bus ("part of AC ESS network" L1 vs "AC EMER BUS, AC ESS BUS not supplied" L2).
3. **Behaviour that is *implied* but not *stated* forces a lot of "assumed" tags.** The notes say "if AC BUS 1 is not available, AC BUS 4 backs up AC ESS" but never define "not available". My first test assumed losing GEN 1 moves AC ESS to AC BUS 4; the engine (correctly per the text) keeps it on the re-fed AC BUS 1. The prompt could ask Phase 0 to add a "0.4b definitions" row (available, connected, reconfiguration) so such words are pinned before coding.
4. **Priority order is missing from the notes, yet the prompt requires a "source priority engine".** L2 mentions a priority table only as a slide. I had to invent: VFG > own EXT > side APU > transfer, single APU GEN = own side only, cross-side tie only with ≥ 2 sources. All tagged, but the prompt should tell the model what to do when the notes have no ordering (it does say "conservative assumption", which I followed, but a suggested default set for ATA 24 would cut guesswork).
5. **Mandatory features exceed what the topic can honestly support.** A 2-channel oscilloscope with time/div, an ammeter and a wattmeter make sense for CIRCUIT, not for a Level-2 SYSTEM page — they end up showing illustrative values (10 A per load, VF shown at 500 Hz), which fights rule 3.3. Suggest making the meter/scope set archetype-dependent (SYSTEM: voltmeter + frequency + Ω/continuity is enough).
6. **"~18 components" vs the real system.** The input asked for ~18, the notes describe ~35 power elements (4 VFG, 2 APU GEN, 4 EXT, 3 BCRU, TR 2, APU TR, 4 BAT, STAT INV, EMER GEN, 11 buses, 25+ contactors). I drew all of them (fewer would break the scenarios); the prompt's split threshold ("> ~25 components → propose a split") therefore triggers on any full ATA 24 chapter and should probably count *sources + buses*, not contactors.
7. **Size budget vs feature list.** All four modes with the mandated features fit in 140 KB only by keeping text terse; the 400 KB (prompt) / 300 KB (this run) limits are fine, but the prompt should state whether the limit is the raw file or gzip, and that "Part 1/Part 2" splitting is measured on the same file.
8. **"Colour-blind-safe with pattern/shape redundancy" is under-specified.** I used hatch fill for shed loads, blade angle for contactors, and text legends on P/BSWs, but AC (amber) vs emergency (magenta) vs DC (green) still differ mainly by colour on wires. A concrete requirement (e.g. dash pattern per network kind) would be easier to meet and to verify.
9. **Minimum 14-px font** is unclear for SVG at variable zoom. State it as "≥ 14 px at fit-to-screen on a 1280-px-wide canvas" or "≥ 14 px CSS in HTML UI; SVG labels ≥ 12 px at fit".
10. **Copyright rule "no more than one quoted sentence per screen"** conflicts with the inspector requirement to show "the note excerpt it comes from" for every component. I kept one short quote per component and only one component is inspected at a time, but the rule should say per-panel or per-component.
11. **Small wording issues:** "Random-fault button and a seeded exam mode" does not say whether exam mode should also hide the instructor panel and fault name (I hid both). The "Instructor" switch is called "password-free" but also "hide-able from students" — hiding a switch that anyone can click has no security value; better to say "collapsed by default".
12. **Level 2 depth vs Fault Lab content.** Phase 4 says Level 3 = troubleshooting/BITE/LRU replacement, but Mode 3 (mandatory) is entirely troubleshooting with LRU replacement. For a Level-2 run the prompt should say how deep Fault Lab goes (I kept it to indications + multimeter + the LRU named in the notes).
